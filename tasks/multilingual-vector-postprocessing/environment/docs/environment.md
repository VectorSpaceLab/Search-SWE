# Runtime and limits

Use `/opt/conda/bin/python` (Python 3.12). The shared GPU image includes CUDA 13.0, CUDA PyTorch 2.9, NumPy, Transformers, SentenceTransformers, FAISS GPU, scikit-learn and normal compiler/system tooling. No pretrained encoder weights or raw text are supplied. Each Compose stage requests one NVIDIA GPU with `count: 1`; the assigned device must be an A100 40GB. Do not assume access to any other host GPU.

The complete agent phase is 21,600 seconds, with 16 CPUs, 16 GiB memory and 100 GiB total task storage including supplied inputs, all model/optimizer/checkpoint/index/cache files. All descendants share these limits. Each container permits at most 512 processes/threads. The image filesystem is read-only. `/app` is a 91 GiB tmpfs, `/tmp`, `/root`, `/var/tmp` are 1 GiB tmpfs each. Their pages count toward the same 16 GiB container memory limit; tmpfs size is a ceiling, not additional RAM. Private `/dev/shm` provides 1 GiB for IPC within that RAM budget. The 256 MiB `/opt/harbor` tmpfs and framework logs/transport are framework facilities and cannot be used as extra training/cache storage. Put the submission in `/app/submission` and other work in `/app`. Source vector directories and `/task` are read-only. No network/data/model APIs are available to task programs.

Read `available_resources.md` and `available_resources.md` for assets and permitted use. There is no required algorithm, starter or training pass count. Public simple baselines can be created with `python /task/baselines/fit.py --method language-center --output /app/submission`; methods identity, pc and whiten are also available. This is optional baseline code, not a requirement.

Submit `transform.py` with `load(submission_dir)` and `transform(vectors, languages, state)`. Inputs are read-only FP32 NumPy matrices B x 1024 (1 <= B <= 128) and lists of two-letter language codes; output is a same-shaped real array/Torch tensor, finite after FP32 conversion and with nonzero finite L2 norms. Load all local weights using the passed directory; the working directory during verification is a writable temporary directory. Both phases have the same runtime libraries. Every needed final file belongs inside `/app/submission`. Submit regular files/directories only; the trusted collector rejects symlinks, sockets, devices and FIFOs.

Run `python /task/runtime/evaluate.py --submission /app/submission --output /app/dev-check` for a public-only development check. The separate verifier applies the same frozen function to batch documents and single queries. It permits normalized-vector L2 differences <= 0.01 in repetition/order/batch checks for floating-point kernel variation. It synchronizes CUDA before transform replies and performs its own normalization and FP32 full-pool cosine retrieval, with ascending document IDs breaking ties. Model loading, document conversion/cache construction and public warmup share 1,800 seconds. Each sequential hidden query has 0.5 seconds including serialization, transform, synchronization, cosine scan, Top-20 and output. There is no training during verification.

When the agent ends or times out, a trusted collector stops remaining processes and freezes/hashes the submission before transferring it. Do not create or alter framework-owned freeze/audit files. The independent candidate process has UID 10001, no new privileges, filesystem/network syscall restrictions, read-only submitted files, and no access to labels, grader, reward files or judge credentials. Integrity and resource violations make the whole score zero; an individual query failure remains zero in its language denominator. A hung/exited transform leaves subsequent unanswered queries failed.
