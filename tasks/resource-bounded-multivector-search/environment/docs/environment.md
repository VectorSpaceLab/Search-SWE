# CPU environment

Both phases use `docker.io/hanhainebula/search-swe-base:cpu-py3.12-1.0.0` (Python 3.12). The interpreter is `/opt/conda/bin/python`; NumPy 2.5.2, FAISS CPU 1.15.0, psutil 7.2.2, PyTorch 2.9.0 CPU, SciPy, scikit-learn, hnswlib, threadpoolctl, orjson 3.12.0, a C++ compiler and OpenMP are installed. The public exhaustive MaxSim library is compiled using `g++ -O3 -mavx2 -mfma -fopenmp -shared -fPIC` and is available at `/task/tools/libmaxsim.so`; its source is alongside it. No GPU is exposed.

Eight cores, 16 GiB memory without swap, 32 GiB storage including public inputs and generated files. Development and all index construction share 7,200 seconds, measured from environment readiness to final artifact collection preparation, including coding-client setup. See the instruction and `/task/tools/runtime_limits.py` for exact final load, warmup and query timing. The prepared index lives at `/app/index`; executable `/app/run.sh` implements the persistent JSONL protocol.

Work as unprivileged `submission` (UID 10001). During development, `/app`, `/tmp`, `/var/tmp`, `/home/submission`, `/dev/shm` and `/run/lock` share one bounded filesystem. Keep delivered files under `/app`; other directories are scratch space. Standard immutable system tools and packages remain outside the data-storage accounting. In the fresh verifier `/app` becomes read-only. Use the `work_dir` from the load request for all runtime writes; `TMPDIR`, `HOME` and `XDG_CACHE_HOME` point there. Do not submit symlinks or special files.

`/task/data/public/corpus/` is the full corpus. `/task/data/public/dev/` contains all official development queries and exact answers. The optional ready baseline index is `/task/data/public/baseline/`; its public source and launcher are `/task/tools/baseline/`. `/task/tools/baseline/run.sh` can be used directly as a checker command or called by your executable `/app/run.sh`. Baseline source includes a corpus-only rebuild script; rebuilding this supplied index is optional. All inputs are read-only. Test queries arrive individually after initialization. Original BEIR query IDs are not exposed in the final protocol.

Run `/opt/conda/bin/python /task/tools/check_submission.py --command /app/run.sh --queries 100` after building your index. Up to 5000 development queries may be requested. The check reports development recall and timing, not an official test score. Compare your candidate and the supplied baseline on the same public query set. Final verification measures the full sequential workload with the sandbox supervisor. Before submission starts it also measures the pinned public baseline, kills its processes and makes its work directory private. Raw submission time is normalized by this same-run baseline against the frozen relative speed target; the raw 600-second query hard limit still applies. Mean Recall@100 must be at least 0.99 before speed earns any reward; all 10,000 hidden queries must complete within 600 seconds.
# Harness logs

Write task data and diagnostics under `/app` or the supplied temporary directories. `/logs` is reserved for the coding harness: new entries there are not permitted, and the harness's own writable log targets share your bounded filesystem. At the end of development, trusted collection stops remaining submission processes and records memory-limit events. Native development timeout or OOM makes the score zero even if a prepared index exists.
