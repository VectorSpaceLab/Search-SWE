An image search request may contain a rough sketch of only part of the desired composition and a description of the complete scene. Build a system that uses these inputs to find the matching artwork in the supplied gallery.

The gallery is at `/task/data/corpus/`. Each row of `records.jsonl` contains `image_id` and `image_path`, with paths relative to that directory. Original gallery images are available. Local image and text encoder weights are at `/task/models/clip/`. Sketches are partial views; they need not depict every element mentioned in the description.

Provide executable `/app/build.sh` and `/app/run.sh`, together with their implementation and learned files under `/app`. The build interface is `/app/build.sh --corpus /task/data/corpus --index-dir /work/index`. The query interface is `/app/run.sh --index-dir /work/index --queries /work/input/queries.jsonl --output /work/output/results.jsonl`. Each input JSONL row contains `query_id`, `description` and `sketch_path`. The sketch path is an absolute path to the current sketch image.

Return the same `query_id` and a `results` list of at most ten distinct gallery images. Each result contains `image_id` and a finite numeric `score`, in nonincreasing score order. Write diagnostics to stderr. Process each sketch-description pair independently; descriptions and results from other requests are not additional context. Computations depending only on the gallery or an image may be cached.

Training pairs and their relevance labels are in `/task/data/training/queries.jsonl` and `/task/data/training/labels.jsonl`. Public validation pairs are at the corresponding paths under `/task/data/validation/`. Labels contain `query_id` and `qrels`, a mapping of gallery image IDs to relevance labels. You may use these inputs to develop and check the system.

You have six hours, 8 CPU cores, 32 GiB RAM, 100 GiB storage and one GPU. The supplied encoders are fixed; scoring or fusion components may use up to 30 minutes of adaptation. The build command has 3,600 seconds. The system must handle up to 1,260 requests in three calls of at most 420 requests, with an independent 1,800-second allowance for each call. Completed valid JSONL rows remain usable if a call times out; missing or invalid rows are unsuccessful. A command failure other than timeout invalidates that call.

Data, models and documentation are read-only. Generate the index at the passed index path. Include required runtime files and learned weights under `/app` so the system works after a fresh start with the supplied gallery, model and current queries. Training and validation labels are not runtime indexing inputs. Use the local resources described in `/task/docs/available_resources.md` and read `/task/docs/environment.md`. Only the first three results contribute to retrieval quality, with more credit for ranking the matching artwork first. Quality is averaged within each of the three description levels, then the levels receive equal weight.

During verification, build and query commands run as a non-root user with `/app` and supplied inputs read-only. The passed index directory already exists and is writable during construction, but its parent directory is not writable. Create build files and temporary directories inside the index directory or the supplied `TMPDIR`; do not create siblings or rename the index directory itself. The completed index becomes read-only for retrieval. Query results, caches and temporary files belong in the writable output directory or the supplied `TMPDIR` and `XDG_CACHE_HOME`. Honor the passed paths rather than writing to `/app` or assuming a writable system temporary directory.

A development-only permissions check is available at `/task/tools/check_runtime.py`; it runs your scripts under these permissions without scoring or reading labels. Run this check from the development root shell. It changes ownership and permissions in `/app` and the check directories in place and does not restore them afterward; the root shell can still edit your files. Keep the writable output directory separate from the index directory; neither directory may contain the other. For example, use `/opt/conda/bin/python /task/tools/check_runtime.py build --corpus /task/data/corpus --index-dir /work/runtime-check/index`. For a query check, use the `query` stage with that index, a public `--queries` path and an `--output` path under `/work/runtime-check/output/`.
